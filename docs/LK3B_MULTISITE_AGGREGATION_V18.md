# LK.3B — агрегация Метрики и Вебмастера по сайтам проекта

Планируемая версия: `2026.08.02.18`

## Зависимость

- установлен и проверен LK.3A / `2026.08.02.17`;
- выбранный проект определяется глобальным контекстом;
- сайты, счётчики Метрики и host ID Вебмастера берутся из `project_sites`.

## Принцип

Проверенные клиенты Яндекс API не переписываются. Новый слой:

1. получает выбранный проект;
2. строит список уникальных источников каждого активного сайта;
3. вызывает существующие сервисы отдельно по каждому сайту;
4. сохраняет исходные результаты сайта;
5. только после этого рассчитывает сводку проекта;
6. возвращает и сводку, и детализацию по сайтам.

## Защита от двойного счёта

- одинаковый `metrika_counter_id` запрашивается один раз;
- одинаковый `webmaster_host_id` запрашивается один раз;
- источник сохраняет список сайтов-владельцев;
- при дублирующей привязке показатель включается в сводку один раз;
- в интерфейсе выводится предупреждение о совместном источнике.

## Метрика

Для каждого уникального счётчика сохраняются:

- `client_id`;
- `project_id`;
- `site_id` или список связанных сайтов;
- `counter_id`;
- период;
- тип набора данных;
- исходный JSON;
- нормализованные показатели;
- статус и ошибка запроса;
- время получения.

Суммируются аддитивные показатели: визиты, пользователи, достижения целей. Процентные показатели рассчитываются повторно по исходным числителям и знаменателям, а не складываются.

## Вебмастер

Для каждого уникального host ID сохраняются:

- показы;
- клики;
- позиция и CTR с корректным взвешиванием;
- запросы и страницы;
- технические проблемы;
- текущие снимки ИКС и индексирования;
- статус и ошибка запроса.

## Ошибки

- ошибка одного источника не отменяет успешные результаты остальных;
- проектная сводка получает статус `complete`, `partial` или `failed`;
- интерфейс показывает сайт и источник с ошибкой;
- старые успешные данные не подменяются пустыми значениями.

## Яндекс Директ

В LK.3B создаётся обязательная связь кабинета/кампании с проектом. Кампания может дополнительно иметь `site_id`. UTM и домен используются только как подсказка для первичного сопоставления.

## Интерфейс

- «Обзор» показывает сводку выбранного проекта;
- каждую карточку можно раскрыть до сайтов и источников;
- «Отчёты» используют ту же сохранённую сводку;
- рядом с показателем видны источник, сайты и время обновления;
- клиент не видит токены и внутренние параметры интеграций.

## Критерии приёмки

- два сайта с разными счётчиками суммируются;
- один счётчик у двух сайтов не удваивается;
- ошибка одного счётчика даёт `partial`, а не пустой отчёт;
- данные разных проектов не смешиваются;
- переключение проекта меняет сводку;
- исходные результаты сохраняются до агрегации;
- повторный запуск за тот же период обновляет набор без дублей;
- фоновые процессы работают без пользовательской сессии;
- `index.php` не изменяется;
- установка поддерживает откат и повторный запуск.

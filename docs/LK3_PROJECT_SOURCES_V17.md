# LK.3 — перевод основных разделов на выбранный проект

Планируемая версия: `2026.08.02.17`

## Зависимость

Работа начинается поверх установленного и проверенного LK.2 / `2026.08.02.16`.

## Главный принцип

Все основные разделы получают единый серверный контекст:

`пользователь → клиент → проект → сайты проекта → источники каждого сайта`.

Ни один API не использует `firstActive()` и не принимает `project_id` без серверной проверки доступа.

## Этапы LK.3

### 1. Источники сайтов

Для каждого `project_sites.id` используются сохранённые настройки:

- `metrika_counter_ids_json`;
- `webmaster_host_ids_json`;
- URL и домен сайта;
- статус сайта;
- дополнительные привязки рекламных источников, которые будут добавлены отдельной таблицей.

### 2. Обзор

- загружается по выбранному проекту;
- агрегирует данные всех активных сайтов проекта;
- позволяет раскрыть показатели по отдельному сайту;
- не смешивает сайты разных проектов;
- рядом с показателем указывает источник и сайты, вошедшие в расчёт.

### 3. Отчёты

- список отчётов фильтруется по выбранному проекту;
- новый отчёт сразу получает `client_id`, `project_id` и при необходимости `site_id`;
- отчёт проекта может включать все сайты или выбранный набор сайтов;
- существующие отчёты без проекта попадают в отдельный список для ручной привязки, а не назначаются автоматически.

### 4. Яндекс Метрика

- запросы выполняются по всем ID счётчиков активных сайтов проекта;
- одинаковый ID счётчика не запрашивается дважды;
- данные сохраняются с `project_id`, `site_id`, `counter_id` и периодом;
- агрегирование выполняется только после сохранения исходных данных по сайтам;
- ошибки одного счётчика не скрывают результаты остальных сайтов.

### 5. Яндекс Вебмастер

- запросы выполняются по всем ID сайтов Вебмастера выбранного проекта;
- данные сохраняются с `project_id`, `site_id`, `webmaster_host_id` и периодом;
- сводка проекта строится из исходных данных сайтов;
- позиции, клики, показы и технические показатели можно раскрыть по сайту.

### 6. Яндекс Директ

- рекламные кабинеты и кампании привязываются к проекту;
- при необходимости кампания дополнительно привязывается к сайту;
- расходы проекта не попадают в другой клиентский проект;
- UTM и домены используются как вспомогательное сопоставление, но не заменяют сохранённую связь.

### 7. Цели

- классифицированная цель получает `site_id` либо признак `project_scope`;
- общая цель проекта не дублируется для каждого сайта;
- цели сайта участвуют только в показателях этого сайта и сводке его проекта;
- существующие цели без сайта сохраняются как общие цели проекта до ручного уточнения.

## Источник каждой цифры

Каждый показатель должен содержать:

- `client_id`;
- `project_id`;
- `site_id` или список сайтов;
- систему-источник;
- внешний идентификатор;
- период;
- способ получения: API, импорт, ручной ввод или расчёт;
- время последнего обновления.

## Права

- администратор и модератор работают со всеми доступными проектами;
- менеджер — только с проектами назначенных клиентов;
- клиент — только просмотр своих проектов;
- подстановка чужого `project_id` или `site_id` возвращает 403.

## Критерии готовности

- переключение проекта обновляет «Обзор» и «Отчёты» без перезагрузки настроек;
- Метрика и Вебмастер используют все активные сайты выбранного проекта;
- ни один запрос не использует первый активный проект;
- данные двух проектов одного клиента не смешиваются;
- проект с несколькими сайтами показывает сводку и детализацию;
- источник каждого показателя доступен в интерфейсе;
- клиентский пользователь не видит внутренние настройки интеграций;
- повторная установка безопасна, `index.php` не изменяется.

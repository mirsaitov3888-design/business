# ЛК: единый контекст клиента, проекта и сайтов

Версия первого этапа: `2026.08.02.14`

## Решение

Иерархия данных портала:

1. Пользователь получает доступ к одному или нескольким клиентам в зависимости от роли.
2. Клиент содержит несколько проектов.
3. Проект содержит несколько сайтов.
4. Все разделы портала работают в контексте выбранного проекта.
5. Сайт внутри проекта является источником данных; по умолчанию показатели агрегируются по всем сайтам проекта.

## Роли

### Администратор и модератор

- видят все доступные клиентские компании;
- выбирают клиента;
- выбирают проект выбранного клиента;
- могут видеть проекты без назначенного клиента для первичной настройки.

### Менеджер

- видит только клиентов, где `clients.manager_user_id` равен его пользователю;
- выбирает проект внутри доступного клиента;
- не может подставить чужой `client_id` или `project_id` вручную.

### Клиент

- работает в одном клиентском ЛК;
- не видит переключатель клиента;
- выбирает проект, если проектов несколько;
- при одном проекте переключатель скрывается;
- получает данные только сайтов выбранного проекта.

## Модель данных

Уже используются:

- `clients`;
- `client_users`;
- `project_client_links`;
- `site_client_links`.

Добавить:

```sql
CREATE TABLE project_site_links (
    site_id BIGINT UNSIGNED NOT NULL,
    project_id BIGINT UNSIGNED NOT NULL,
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (site_id),
    KEY idx_project_site_project (project_id)
);
```

Один проект может содержать много сайтов. Один сайт относится только к одному проекту.

## Серверный контекст

Добавить `PortalContextService`:

- `accessibleClients()`;
- `accessibleProjects(?int $clientId)`;
- `accessibleSites(int $projectId)`;
- `resolveClientId()`;
- `resolveProjectId()`;
- `requireProject(int $projectId)`;
- `requireSite(int $siteId, int $projectId)`.

Каждый API обязан проверять выбранный проект на сервере. Скрытие фильтра в интерфейсе не является защитой.

## Хранение выбора

- основной источник выбора — `client_id` и `project_id`, передаваемые каждым API-запросом;
- последний выбор сохраняется в PHP-сессии для восстановления после перезагрузки;
- браузер хранит последний проект только как UI-удобство;
- сервер всегда повторно проверяет доступ пользователя.

## Глобальный интерфейс

Добавить верхний контекстный фильтр:

- администратор/модератор: `Клиент` + `Проект`;
- менеджер: доступный `Клиент` + `Проект`;
- клиент: только `Проект`, если их больше одного;
- подпись: количество сайтов в выбранном проекте;
- событие браузера `portal:context-changed` для перезагрузки разделов.

## Экономика

P1.3 начинается только после перевода всех источников на выбранный проект. Иначе расходы и продажи могут относиться к разным проектам, а CPL, CPQL, стоимость договора, ROAS и ROMI будут недостоверны.

## Критерии готовности первого этапа

- администратор выбирает клиента и проект;
- менеджер не видит чужих клиентов и проектов;
- клиент не видит переключатель клиента;
- клиент видит только свои проекты;
- выбранный проект сохраняется после обновления страницы;
- P1-сделки и цели переключаются между проектами без смешения данных;
- попытка передать чужой `project_id` возвращает 403;
- проект возвращает список всех связанных сайтов;
- `index.php` не изменяется;
- повторная установка безопасна;
- есть резервная копия и автоматический откат.

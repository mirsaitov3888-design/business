# ЛК: единый контекст клиента, проекта и сайтов

Версия первого этапа: `2026.08.02.14`

## Иерархия

1. Пользователь получает доступ к клиентам по своей роли.
2. Клиент содержит несколько проектов.
3. Проект содержит несколько сайтов.
4. Все данные портала должны запрашиваться в контексте выбранного проекта.
5. По умолчанию показатели проекта агрегируются по всем его сайтам.

## Роли

### Администратор и модератор

- видят все компании;
- выбирают клиента и проект;
- могут открыть проект без назначенного клиента для его настройки.

### Менеджер

- видит клиентов, где `clients.manager_user_id` равен его пользователю;
- выбирает доступный проект;
- не может передать чужой `client_id` или `project_id` вручную.

### Клиент

- работает внутри одного клиентского ЛК;
- не видит переключатель клиента;
- выбирает проект, когда проектов несколько;
- при одном проекте переключатель скрывается;
- получает данные только выбранного проекта и его сайтов;
- в первом этапе видит сделки и цели без права изменения.

## Канонический реестр сайтов

Используется отдельная таблица `project_sites`, не зависящая от конкретного модуля мониторинга:

```sql
CREATE TABLE project_sites (
    id BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
    project_id BIGINT UNSIGNED NOT NULL,
    name VARCHAR(190) NOT NULL,
    url VARCHAR(1000) NOT NULL,
    host VARCHAR(255) NOT NULL,
    status VARCHAR(30) NOT NULL DEFAULT 'active',
    metrika_counter_ids_json JSON NULL,
    webmaster_host_ids_json JSON NULL,
    source_type VARCHAR(40) NOT NULL DEFAULT 'manual',
    source_id BIGINT UNSIGNED NULL,
    PRIMARY KEY (id),
    UNIQUE KEY uniq_project_sites_url (project_id, url(190))
);
```

При установке URL безопасно переносятся из:

- `projects.site_url`;
- `site_monitors.url`;
- `monitored_sites.base_url`.

Один проект может содержать любое количество сайтов. Один сайт в реестре относится к одному проекту.

## Серверный контекст

`PortalContextService` отвечает за:

- доступных клиентов;
- доступные проекты;
- сайты выбранного проекта;
- восстановление последнего выбора;
- серверную проверку `project_id`;
- запрет доступа к чужому проекту.

Последний выбор сохраняется в PHP-сессии и таблице `user_portal_context`. Интерфейс не считается средством защиты: каждый API повторно проверяет доступ на сервере.

## Глобальный фильтр

В верхней части ЛК выводится:

- администратору и модератору — `Клиент` и `Проект`;
- менеджеру — доступный клиент и проект;
- клиенту — только проект, когда их больше одного;
- всем ролям — количество сайтов выбранного проекта.

После смены проекта сохраняется новый контекст и перезагружаются данные разделов.

## Экономика

P1.3 начинается после перевода источников на выбранный проект. До этого расходы и продажи могут относиться к разным проектам, поэтому CPL, CPQL, стоимость договора, ROAS и ROMI нельзя считать достоверными.

## Критерии готовности `.14`

- администратор выбирает клиента и проект;
- менеджер не видит чужие компании и проекты;
- клиент не видит переключатель клиента;
- клиент видит только свои проекты;
- выбранный проект сохраняется после обновления страницы;
- сделки и цели переключаются без смешения данных;
- чужой `project_id` отклоняется сервером;
- проект возвращает все связанные сайты;
- `index.php` не изменяется;
- повторная установка не дублирует ресурсы и сайты;
- создаётся резервная копия и работает автоматический откат.

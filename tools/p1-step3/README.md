# P1.3 — экономические показатели

Целевая версия: `2026.08.02.14`.

## Назначение

Объединить рекламные расходы из отчётов с фактическими сделками из P1.1 и подготовить единый проверяемый расчёт:

- CPL;
- CPQL;
- стоимость договора;
- ROAS;
- ROMI.

## Источники

1. `report_channels` — расходы, клики и количество заявок по каналу.
2. `sales_records` — квалификация, договоры, сумма договора, оплаченная выручка и валовая маржа.
3. `conversion_goals` — правила того, какие цели считаются лидами, вспомогательными и микроконверсиями.

## Правила расчёта

- CPL = расходы / лиды.
- CPQL = расходы / квалифицированные лиды.
- Стоимость договора = расходы / количество договоров.
- ROAS = оплаченная выручка / расходы.
- ROMI = (валовая прибыль − расходы) / расходы × 100%.
- Деление на ноль возвращает `null`, а не `0`.
- ROMI не рассчитывается, пока для оплаченной выручки не хватает данных о марже.
- Не классифицированные, вспомогательные и микроконверсии не увеличивают количество лидов.

## Защита от двойного счёта

- Пользователь выбирает один отчёт-источник расходов.
- Сделки фильтруются по проекту, периоду и каналу.
- Одна сделка учитывается один раз по `sales_records.id`.
- Несопоставленные каналы показываются отдельной строкой и не скрываются.
- В каждом показателе сохраняется происхождение числителя и знаменателя.

## Интерфейс

В разделе «Продажи и экономика» появится вкладка «Экономика»:

- выбор отчёта и периода;
- итоговые карточки CPL, CPQL, стоимости договора, ROAS и ROMI;
- таблица по каналам;
- предупреждения о неполных данных;
- раскрываемая расшифровка источников каждой цифры.

## Критерии приёмки

- расчёты совпадают с контрольными примерами;
- отсутствующие данные не подменяются нулями;
- изменение сделки сразу влияет на повторный расчёт;
- удалённая сделка больше не учитывается;
- повторный запуск установщика не дублирует таблицы, CSS и JavaScript;
- `index.php` не изменяется;
- тесты выполняются на MySQL 8.4;
- перед изменениями создаётся резервная копия, при ошибке выполняется откат.
